Executive summary

The platform is broadly functional. All 20 advisor pages and the member portal load and render real backend data. Core CRUD works for clients, members, and member-submitted travel requests, and two of the three AI features (Proposal Co-Pilot and Client Intelligence) generate real output through the local Ollama model. Five issues block a clean production-grade experience, the most serious being the Morning Briefing timing out and a shared-cookie conflict that locks members out of the portal if they have ever logged into the advisor side.

Detailed findings

Critical

F-1 · Morning Briefing fails with 504 Gateway Timeout

Clicking Generate Briefing on /briefing shows the spinner, then silently resets to the idle state. The network call to /api/briefing/morning-briefing returns 504. The briefing is the only AI route that times out; the streaming proposal and the synchronous intelligence call both succeed (intelligence took 44.5s, under the proxy ceiling). The briefing endpoint appears to exceed the Cloudflare or APISIX origin timeout.

  • Where: /api/briefing/morning-briefing returns 504.
  • Why: The non-streaming briefing call runs longer than the proxy timeout window, or the underlying prompt aggregates too much for one synchronous request.
  • Fix: Convert the briefing to streaming (SSE) like the proposal engine, or raise the origin timeout for this route and add a hard ceiling on prompt size. Surface the error to the user instead of silently resetting.
Critical

F-2 · Member portal login fails when an advisor session cookie exists

After signing into the advisor portal, visiting /client and signing in as a member returns a successful login response (the member object is returned), but the page never navigates to the dashboard. memberAuth.me returns null. The advisor cookie app_session_id and the member cookie lanai_member_session coexist on the same domain; the request context resolves the advisor session first, so the member context is never recognised. Clearing the advisor cookie lets the member log in immediately.

  • Where: Shared domain lanai.newfire.app; both portals set cookies at root path.
  • Why: The context builder prefers the advisor session, so a member who also has an advisor cookie cannot authenticate as a member.
  • Fix: Scope cookies by path (/ for advisor, /client for member), or make member auth resolution independent of the advisor cookie. This is a realistic real-world conflict since both portals live on one domain.
High

F-3 · Proposal Co-Pilot submits without the required Structured Request (422)

The Generate Proposal button is enabled before the required Structured Request dropdown is selected. Clicking it returns 422 from /api/proposals/generate-proposal-stream and the output panel stays on its placeholder. Selecting a structured request first produces a full proposal correctly (5000+ characters, itinerary, premium delivery panel).

  • Fix: Disable Generate until a structured request is selected, or auto-select the member's most recent request, and show a client-side validation message instead of relying on the 422.
Medium

F-4 · Production CSP blocks Google Fonts

The response Content-Security-Policy sets style-src 'self' 'unsafe-inline' with no fonts.googleapis.com origin, so the Playfair Display, DM Sans, and JetBrains Mono stylesheet is blocked on every page. The app renders with fallback system fonts, which softens the brand identity in production even though it looks correct in local dev.

  • Fix: Add fonts.googleapis.com to style-src and fonts.gstatic.com to font-src, or self-host the font files and serve them from 'self'.
Medium

F-5 · Clients page is create and read only (no edit or delete in UI)

The Clients page exposes Add Client and search, but no edit or delete control on a row or detail view. The clients.remove API procedure exists, so deletion is possible by API but not from the interface. Created a QA client successfully (15 to 16 records, record appears in the list and search).

  • Fix: Add row-level edit and delete actions, gated by role, to match the create flow.
Info

F-6 · Member Document Vault is empty

The member-side Document Vault loads with "No documents yet." This matches the codebase: memberPortal.myDocuments is a stub that returns an empty array. Advisors can attach document records, but members see nothing. Not a crash, but a feature advertised to members that does not yet deliver.

Info

F-7 · Data quality: duplicate WhatsApp client records

The Clients list contains 9 duplicate rows named "WhatsApp 1181" (phone 6315551181), and a member named "WhatsApp 1181" with a placeholder email sits in the Members list. The WhatsApp integration is creating a new client record per inbound message instead of deduplicating by phone number.

  • Fix: Deduplicate client creation on phone number in the WhatsApp ingestion path; merge or archive the existing duplicates.
Info

F-8 · Seeded advisor@lanai.test cannot sign in on production

Signing in as advisor@lanai.test redirects through Keycloak and returns {"error":"Keycloak authentication failed"} with HTTP 401 on the callback. The account exists in the local Keycloak realm but is not provisioned (or lacks the required role or verified email) in production. devadmin works. Worth fixing if that account is meant to be a demo advisor.
